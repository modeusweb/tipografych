# Типографыч

**Типографыч** — современный русскоязычный онлайн-типограф: вставьте текст, обработайте, проверьте
изменения и скопируйте результат. Всё обрабатывается **локально в браузере**, текст
никуда не отправляется.

> «Вставил текст → обработал → проверил изменения → скопировал результат».

## Возможности

- **Кавычки**: прямые и английские → «ёлочки», вложенные (включая английские “ ”
  внутри «ёлочек») → „лапки“ (stateful-алгоритм); лишняя точка после закрывающей
  кавычки убирается, если цитата уже завершена знаком («…дней…». → «…дней…»).
- **Тире и минус**: дефис с пробелами → длинное тире; латинский префикс
  склеивается дефисом («IT - индустрии» → «IT-индустрии»), а «HTTP - это»
  остаётся тире; диапазоны «2020-2025» → «2020–2025» (в том числе уже
  набранные «5—10»); дефис перед числом → минус («-10 °C» → «−10 °C»);
  разорванное дефисное слово («кто - то», «как- либо», «всё - таки»,
  «точь - в - точь») склеивается обратно в «кто-то».
- **Пробелы**: двойные, в начале/конце строк, вокруг пунктуации, в скобках и кавычках;
  внутри двухбуквенных сокращений вместо обычного ставится неразрывный пробел
  («т.е.» → «т. е.» — при переносе строки «е.» не оторвётся).
- **Пустые строки**: три и более переводов строки подряд → одна пустая строка
  (абзацы и одиночные переносы сохраняются; исключение — короткое слово в конце
  строки: оно стягивается со следующей строкой, см. «Неразрывные пробелы»).
- **Многоточие**: `...` и `. . .` → `…`, диапазоны «10...12» → «10…12».
- **Символы**: «(c)», «(r)», «(tm)» (и кириллические «(с)», «(тм)») → ©, ®, ™;
  дроби «1/2», «3/4» → ½, ¾; «5х5» → «5×5»; стрелки «->», «<-», «<=>» → →, ←, ⇔.
- **Валюты**: «90руб.», «5000 рублей» → «90 ₽», «5000 ₽»; знак валюты не
  разъединяется с числом («20$», «$20» остаются слитными); буквенные
  обозначения отбиваются от числа («100долл.» → «100 долл.»); отбивка знака
  от числа («5000$» → «5000 $») и перенос знака за число («$100» → «100 $») —
  правила пресета «Издательская».
- **Имена**: имя после обращения, звания или должности капитализируется —
  «коллега петров а. н.» → «коллега Петров А. Н.» (без обращения имя не трогается).
- **Сокращения**: «01.01.2026г.» → «01.01.2026 г.», «2025-2026гг.» → «2025-2026 гг.».
- **Неразрывные пробелы**: предлоги (в том числе «из-за», «из-под»), союзы, инициалы,
  №/§, числа и единицы. Короткое слово в конце строки стягивается со следующей
  строкой, поэтому предлог не «висит» на переносе.
- **Числа и единицы**: разделители разрядов (5+ цифр, опционально), «10кг» → «10 кг»,
  «1500м2» → «1500 м²», «Мбит / сек» → «Мбит/сек»; лишняя точка после единиц СИ
  внутри предложения убирается («15 кг. веса» → «15 кг веса», но в конце
  предложения точка остаётся).
- **Температура**: «20 градусов Цельсия» → «20 °C», «+ 25С», «(+25 С)» → «+25 °C»
  (после знака «+»/«−» пробел убирается, кириллическая «С» становится латинской).
- **Проценты**: «50 %» → «50%», дробь через точку → запятая: «0.5 %» → «0,5%».
- **Телефоны**: «+7 ( 999 ) 123 - 45 - 67» → «+7 (999) 123-45-67», после чего
  номер защищается от остальных правил.
- **Защита фрагментов**: URL, email, телефоны, даты, IP, версии, файлы (в том числе
  «голые» расширения вроде «.psd» и «.fig», плюс дизайн-форматы sketch/xd/ai/cdr/indd),
  флаги CLI, inline-код, fenced-блоки, HTML-теги и ссылки Markdown не трогаются.
  В формате Markdown защищаются также блоки кода с отступом (4+ пробела или таб) —
  вместе с отступами, чтобы разметка не поехала.
- **Просмотр изменений**: режим «Изменения» с построчным diff и подсветкой.
- **Настройки**: пресеты (Русская типографика / Минималистичная / Издательская /
  Пользовательская), отдельные правила, формат входных данных, автообработка.
- **Прочее**: светлая/тёмная/системная тема, TXT-импорт и драг-н-дроп, экспорт в TXT,
  undo/redo, горячие клавиши `Ctrl+Enter`, `Ctrl+Shift+C` и `Ctrl+A`
  (выделяет содержимое панели «Результат», когда панель в фокусе — независимо от раскладки).

## Технологии

Next.js 16 (App Router), React 19, TypeScript (strict), Tailwind CSS 4, Heroicons,
Vitest. Основной инструмент — обычный `textarea`, без тяжеловесных rich-text редакторов.

## Архитектура

```
src/
  app/            layout, страница, стили, favicon
  components/
    editor/       текстовое поле, файлы, счётчики
    result/       результат, статистика, состояния
    diff/         построчный diff
    settings/     drawer настроек
    help/         справочное окно
    ui/           кнопки, переключатели, модальные окна
  features/typography/        ТИПОГРАФИЧЕСКИЙ ДВИЖОК (без UI)
    rules/        правила, по одному модулю на файл
    protection.ts система «protected tokens»
    pipeline.ts   конвейер: нормализация → защита → правила → восстановление
    presets.ts    готовые профили правил
    diff.ts       diff для «Показать изменения»
    config.ts     центральная конфигурация
  hooks/          тема, настройки, счётчики
  lib/            clipboard, download, worker-клиент, форматирование
  workers/        typography.worker.ts (тяжёлая обработка)
```

**Главный принцип**: UI не содержит бизнес-логики типографики. Движок полностью
независим от React и браузера — его можно использовать в Node.js, CLI или тестах.

### Конвейер обработки

```
Input
  ↓ 1. Нормализация (переводы строк, вырезание приватных Unicode-символов)
  ↓ 2. Предварительная обработка: правила с флагом `runBeforeProtection`
        (форматирование телефонов, сокращение года — им нужны «сырые» даты и телефоны)
  ↓ 3. Защита фрагментов (protected tokens)
  ↓ 4. Правила в фиксированном порядке (см. rules/index.ts):
         кавычки → многоточие → пробелы у знаков пунктуации → тире → диапазоны →
         скобки → символы (©/®/™, дроби, знак умножения, стрелки) → проценты →
         температура → единицы измерения → валюты → разряды чисел → двойные пробелы →
         края строк → пустые строки → заглавные буквы в именах → неразрывные пробелы
         (предлоги, инициалы, №, единицы) → сокращения (в том числе «г.» перед городом
         и после года)
  ↓ 5. Восстановление защищённых фрагментов
Output
```

Порядок задокументирован прямо в реестре правил (`rules/index.ts`).

### Система «protected tokens»

Перед обработкой фрагменты, которые нельзя изменять, заменяются маркерами из
приватной зоны Unicode:

```
https://example.com  →  \uE000 1b \uE001   (U+E000 + индекс в base36 + U+E001)
```

Символы U+E000–U+E001 не встречаются в паттернах правил, поэтому кавычки, тире
и пробелы «внутри» защищённых фрагментов недоступны. После обработки токены
восстанавливаются на свои места. Пользовательские символы U+E000/U+E001
вырезаются на этапе нормализации, поэтому конфликтов не бывает.

### Система правил

```ts
interface TypographyRule {
  id: string;            // стабильный ID: "dash-sentence"
  name: string;          // «Тире в предложениях»
  description: string;   // показывается в настройках
  category: RuleCategory;
  enabledByDefault: boolean;
  runBeforeProtection?: boolean; // выполнять до защиты фрагментов (телефоны, даты)
  apply(text: string, ctx: RuleContext): string; // чистая функция
}
```

##### Как добавить новое правило

1. Создайте `src/features/typography/rules/<id>.ts` с объектом `TypographyRule`.
2. Подключайте замены через `applyRegex(ctx, rule, text, regex, map)` — он
   автоматически регистрирует каждое фактическое изменение в статистике.
3. Зарегистрируйте правило в `rules/index.ts` **в нужном месте конвейера**.
   Если правилу нужны «сырые» фрагменты (даты, телефоны), которые protection
   заменяет токенами, поставьте `runBeforeProtection: true`.
4. Добавьте тест в `src/features/typography/__tests__/`.
5. Если правило спорное — сделайте `enabledByDefault: false` или отдельный пресет.

### API движка

```ts
import { typograph } from "@/features/typography";

const result = typograph('Он сказал - "Привет"...', {
  enabledRules: ["quotes-russian", "dash-sentence", "ellipsis"],
  protection: {},          // пустые поля = значения по умолчанию (всё защищено)
  format: "plain",         // "plain" | "markdown" | "html"
});

// {
//   text: "Он сказал — «Привет»…",
//   changed: true,
//   statistics: { totalChanges, byRule, byCategory, counts },
//   samples: [{ ruleId, category, before, after, count }],
// }
```

Защищённые фрагменты можно забирать отдельно:

```ts
import { protectFragments } from "@/features/typography";

const guarded = protectFragments(text, protection, format);
const processed = runRules(guarded.text); // любая логика
const restored = guarded.restore(processed);
```

### Web Worker

Тексты длиннее `TYPOGRAPHY_CONFIG.workerThresholdChars` (50 000 символов)
обрабатываются в `typography.worker.ts`, чтобы интерфейс оставался отзывчивым.
Клиент (`lib/worker-client.ts`) прозрачно пробует создать Worker и при недоступности
или сбое использует синхронный путь. Каждый запрос получает `requestId`,
устаревшие ответы игнорируются (отмена устаревших результатов).

### Производительность

- Правила — линейные проходы регулярных выражений без рекурсии.
- Diff — Myers O(ND) **по строкам** с лимитами (`diffMaxLines`, `diffMaxDistance`);
  для огромных текстов diff отключается, остаётся сводка изменений.
- Счётчики текста считаются с debounce; точный размер в байтах — только для
  больших текстов.
- Примеры изменений ограничены (`maxSamples: 300`), статистика — один счётчик
  на правило.

### Лимит текста

Лимит задаётся в `src/features/typography/config.ts`:

```ts
maxInputSizeBytes: 5 * 1024 * 1024, // 5 МБ
```

При превышении редактор показывает понятное сообщение и блокирует обработку.

## Тестирование

```bash
npm test
```

Покрыто:

- построчное поведение правил (пробелы, пустые строки, пунктуация, кавычки, тире,
  диапазоны, скобки, символы ©/®/™, дроби, знак умножения, стрелки, проценты,
  числа, единицы, температура, неразрывные пробелы, сокращение года);
- защита URL, email, телефонов, дат, IP, версий, файлов, кода, HTML, Markdown;
- **идемпотентность**: `typograph(typograph(text)) === typograph(text)`;
- регрессии аудита: полный «стресс-текст» пользователя (вложенные кавычки,
  пустые строки, символы, дроби, стрелки, сокращение года), второй аудит
  (разорванные дефисы, «голые» расширения файлов, точка после кавычки,
  неразрывные пробелы в «т. е.») и третий (латинский префикс «IT - индустрия»,
  «(+25 С)» → «(+25 °C)», точка после единиц СИ, диапазон «5—10» в скобках);
- fuzz-тесты: случайные тексты не падают, не зацикливаются, токены всегда
  восстанавливаются;
- производительность: обработка ~380 КБ укладывается в лимит времени.

## Известные ограничения

- Разделители разрядов включаются только для чисел из **5+ цифр** и не входят
  в пресет «Минималистичная»: у длинных чисел бывает контекст (артикулы, коды),
  который нельзя распознать без подготовки.
- Запись «20 градусов» без указания шкалы не трогается — нет уверенности, что это
  температура. Знаковая температура без символа градуса распознаётся по знаку
  «+»/«−» («+ 25С» → «+25 °C»), поэтому формула вида «A + 3C» может быть понята
  как температура — правило отключаемо.
- Имя капитализируется только после обращения, звания или должности и только
  вместе с инициалами: «его коллега петров а. н.» → «его коллега Петров А. Н.»,
  а «его коллега сказал» и одиночное «петров» остаются как есть.
- Короткое слово в конце строки стягивается со следующей строкой, поэтому число
  строк может измениться. Абзацы, заголовки, цитаты, списки, реплики диалога и
  строки из одного слова не склеиваются; правило отключаемо.
- Разорванное дефисное слово склеивается только для заведомых дефисных пар
  («кто - то», «какой - либо», «во - первых», «точь - в - точь»): конструкция
  с правой частью вне списка («Он пришёл - проверить») остаётся тире.
- Латинский префикс склеивается дефисом только для капс-аббревиатур
  («IT - индустрия», «VIP - зал», «B2B - маркетинг»): латинское слово
  в смешанном регистре («Instagram - популярная соцсеть») и конструкция
  со сказуемым («HTTP - это протокол») остаются тире. Устойчивое сочетание
  «как попало» по словарю пишется раздельно и не склеивается.
- Апострофы и одиночные кавычки не нормализуются (сохраняются как есть).
- Схлопываются только **три и более** перевода строки подряд: одна пустая строка
  между абзацами — это осознанная структура текста, она сохраняется.
- Дроби заменяются только для известных значений («1/2», «3/4» и др.) и только когда
  слэш стоит ровно между числами: «11/2» и «1/2/3» не трогаются.
- Знак умножения ставится между числами («5х5» → «5×5»); hex-литералы («0x1F»)
  и буква на границе слова («2х-комнатная») сохраняются.
- Знак рубля ₽ ставится только после числа: «руб.» без предшествующей цифры остаётся
  словом. Знак валюты не разъединяется с числом: «20$», «$20» остаются слитными.
  Отбивка («5000$» → «5000 $») и перенос знака за число («$100» → «100 $») —
  спорные записи, включаются правилами пресета «Издательская».
- Дефис перед числом становится минусом («-10» → «−10»); диапазоны («5-6»),
  телефоны и идентификаторы («ISO-8601») не трогаются.
- В формулах переменные в скобках не заменяются на ©: «(c)» рядом со знаком
  операции («A (c) = B + C») считается переменной, а не знаком охраны прав.
- Начинающие пробелы строк (отступы) удаляются правилом «Пробелы в начале и конце
  строк» — это отключаемое правило. В формате Markdown блоки кода с отступом
  при этом защищены и сохраняются как есть.
- Внутристроковая подсветка diff работает по принципу «общее начало/конец» —
  сложные перестановки показываются как замена целой строки.
- Часть правил использует консервативные эвристики (например, латинские сокращения
  `e.g.` не разрываются) — приоритет всегда «не испортить текст».

## Приватность

Текст обрабатывается исключительно в вашем браузере и не отправляется на сервер.
В `localStorage` хранятся только настройки интерфейса (пресет, правила, тема),
сам текст не сохраняется.

## Contribution (вклад в проект)

Приветствуются любые вклады: баг-репорты, идеи новых правил типографики,
улучшения UI и документации.

1. Сделайте форк репозитория и создайте ветку от `master`:
   ```bash
   git checkout -b feature/my-feature
   ```
2. Установите зависимости и запустите проверку перед коммитом:
   ```bash
   npm install
   npm run lint && npm run typecheck && npm test
   ```
3. Для нового правила типографики: создайте модуль в
   `src/features/typography/rules/`, зарегистрируйте его в `rules/index.ts`
   и добавьте unit-тесты в `src/features/typography/__tests__/`.
   Движок обязан оставаться идемпотентным: `typograph(typograph(text)) === typograph(text)`.
4. Оформите коммит и откройте Pull Request в `master` с понятным описанием
   изменений (что и зачем). Скриншоты для изменений UI — приветствуются.

Баг-репорты: опишите шаги воспроизведения, ожидаемое и фактическое поведение,
приложите пример текста (без личных данных).
